How “From Noise to Signal” was built

A scroll-driven WebGL film where fifteen thousand particles act out the story — chaos, lens, flow, order, and finally the brand itself.

StackHTML + CSS + Three.js (vendored)
Particles15,000 desktop / 7,000 mobile
ShadersCustom GLSL vertex + fragment
Images usedNone

The concept

Ikigai Engine's promise is turning noise into signal, so the site literally performs it. One fixed full-screen canvas holds a single particle system, and as you scroll through six "acts," the particles morph between five formations that mirror the copy: a chaotic nebula (the fog you run your business in) → a lens iris (see it) → braided flow streams (automate it) → an ordered lattice (information in its place) → the word IKIGAI (the finale signature). The prose scrolls normally in front of it, so the story reads even if you never notice the choreography — but you notice.

Morphing 15,000 particles

Every formation is precomputed on the CPU as a Float32Array of XYZ targets and uploaded once as vertex attributes (aP0…aP4). The GPU does all the movement: a single uniform uSeg (e.g. 2.35 = 35% of the way from formation 2 to 3) drives a smoothstep mix in the vertex shader. No per-frame buffer updates, so it runs at 60fps even on phones.

float f = floor(uSeg), t = fract(uSeg);
// per-particle stagger so morphs ripple instead of snapping
float tt = clamp(t*1.35 - aSeed*.35, 0., 1.);
tt = tt*tt*(3.-2.*tt);                    // smoothstep
vec3 p = mix(pick(f), pick(f+1.), tt);
p += breathingNoise(aSeed, uTime);        // idle life

Each particle also carries a random aSeed, used three ways: to stagger the morph (particles leave in waves, like a murmuration), to vary point size, and to animate a tiny idle drift so the system never looks frozen. Color cross-fades per formation — cold slate for the fog, cyan for the lens, amber for the machine, mint for the lattice, gold for the finale — with additive blending and a soft radial falloff in the fragment shader so overlapping points glow like film grain.

The word finale

The "IKIGAI" formation is sampled from a hidden 2D canvas: draw the word with fillText, read back getImageData, keep every 2nd pixel above a brightness threshold, and map those pixel coordinates into world space. Because target positions are just another attribute, the same shader that scattered the nebula also spells the logotype. On phones the sampling box is scaled down so the word fits a narrow viewport.

Scroll direction

No scroll-jacking. The page scrolls natively; a tiny function maps the viewport's center against each act's midpoint and interpolates piecewise between formation indices. The render loop then eases toward it (cur += (target-cur)*.085) so fast flicks settle cinematically rather than teleporting. The camera dollies in slightly across the film and follows the mouse a few degrees for parallax.

The cinema dressing

  • Letterbox opening — two black bars ease off-screen 150ms after load, and the header/nav fades in late, like titles.
  • Film grain — a fixed overlay using an SVG feTurbulence data-URI with mix-blend-mode: overlay. Costs one element, sells the "shot on film" texture.
  • Acts, not sections — Roman-numeral ghost numerals (-webkit-text-stroke outlines), a gold progress rail with chapter dots, italic Cormorant Garamond against light Outfit.
  • Type pairing — the serif's italics carry emotion ("clearly", "for your business"); the geometric sans keeps the operator voice matter-of-fact.

Performance & fallbacks

  • Pixel ratio capped at 1.5× desktop; particle count halved on mobile; rendering pauses when the tab is hidden.
  • If WebGL is unavailable or prefers-reduced-motion is set, the canvas is removed and a layered radial-gradient backdrop takes over — every word of the page still works.
  • Three.js is self-hosted (module + core, ~150KB gzipped) so the site has zero third-party requests.

Lessons if you build one

  • Put morph targets in attributes and drive everything with one uniform — the CPU should whisper, not shout.
  • Stagger per-particle timing with a seed; simultaneous motion reads mechanical, rippled motion reads alive.
  • Let text scroll normally on top of the film. Scroll-jacking is where cinematic sites go to die on phones.
  • Design the fallback first: if the site converts with the canvas deleted, the canvas is pure upside.
