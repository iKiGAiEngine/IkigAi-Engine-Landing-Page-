How the kinetic type site was built

No illustrations, no 3D, no photography. One variable font under tension, and a page that moves the way the copy sounds.

01A font as the engine

Anybody is a variable font with a width axis running from 50 (compressed) to 150 (expanded). That axis is the whole site. The three method words — SEE IT. / AUTOMATE IT. / LET AI LIFT. — are physically stretched by your scroll position: a scroll handler measures each word's distance from the viewport center and maps it to font-variation-settings: 'wdth' …, so words inhale as they approach the middle of the screen and exhale as they leave.

const c = (rect.top + rect.height/2) / innerHeight;
const t = 1 - Math.min(1, Math.abs(c - .5) * 2);   // 1 at center
el.style.fontVariationSettings = `'wdth' ${60 + t * 65}`;

Because it's a real variable axis (not transform: scaleX), the letterforms re-draw correctly — stems stay upright, counters open up. That's the difference between typography moving and typography being smeared. The service-index rows and pain-list lines use the same axis on hover, easing from condensed to wide with a long cubic-bezier.

02Velocity-reactive marquees

The two marquee bands don't run on CSS animations — a requestAnimationFrame loop advances their translateX manually, so their speed can react to scroll velocity. Scroll fast and the bands whip and skew like they've caught your momentum; stop and they settle back to a lazy drift. Velocity is smoothed with an exponential moving average so it never jitters:

vel += (dy - vel) * .08;                  // smooth
offset -= dir * (1.2 + |vel| * .12);      // speed
track.style.transform =
  `translateX(${offset}px) skewX(${-vel * .18}deg)`;

03The scramble-in

The hero words slam up from clipped containers (pure CSS keyframes with staggered delays), while a decoder effect churns their glyphs through #$%&@=+* before locking in the real characters left-to-right over ~26 frames. It's about 15 lines of JS and it sets the tone in the first half-second: this page is typographic machinery.

04Brutalist discipline

  • Two fonts, three colors, zero border-radius. Anybody for display, Space Mono for everything else; black, bone-white, and one acid green. Constraint is what makes the loud parts loud.
  • The header uses mix-blend-mode: difference, so it stays legible over black, bone, and acid sections without a background — and turns an odd blue over the acid panel, which is exactly the kind of glitch brutalism keeps.
  • The before/after "swap" is a full-bleed acid panel: strikethrough mono on the left, condensed display caps on the right. High contrast does the persuading.
  • The CTA is a landmass — a full-width acid block whose headline widens on hover (same wdth axis) and whose arrows shove right. You cannot miss it, which is the point of a CTA.

05Keeping it usable

  • Everything falls back gracefully: prefers-reduced-motion kills the marquee loop, the scramble, and the scroll-stretch (words rest at wdth 100).
  • On phones the stretch is capped (wdth ≤ 108) and the method words drop to a size that survives 390px, because a word that clips off-screen isn't kinetic, it's broken.
  • Scroll handlers are throttled through requestAnimationFrame; the marquee is the only persistent loop and it moves two elements with transforms only — no layout thrash.

06Lessons if you build one

  • Variable fonts are the highest power-to-weight animation tool on the web: one file, infinite in-betweens, GPU-cheap.
  • Map motion to user input (scroll position, velocity, hover) rather than timelines — it makes the page feel operated instead of watched. Fits a brand that automates things.
  • Loud design needs quiet lines: keep body copy small, mono, and dim so the display type owns the room.
